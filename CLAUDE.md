# CLAUDE.md — County Sustainability Planner (working title)

Project plan and implementation guide. Read this before writing code. Facts about
external data and programs were checked on 2026-11-13; anything marked **VERIFY**
was not checked and must be confirmed before you rely on it.

---

## 1. What we are building

A web app for local government officials, mainly in less wealthy and rural US
counties. The official selects a county and gets:

1. **Needs** — measurable sustainability gaps in that county.
2. **Assets** — specific local sites and natural resources that could host a fix.
3. **Opportunities** — a ranked list pairing a need with an asset and a solution,
   with a rough size estimate and a funding program that could pay for it.
4. **A short written brief** per county, generated by Gemini from our numbers.

One-line pitch: *"Pick your county, see your biggest sustainability gaps, the
local sites that could fix them, and how to pay for it."*

### Constraints that shape every decision

| Constraint | Consequence |
|---|---|
| Hackathon, 24–48 hours | No database, no auth, no Docker, no data pipeline. |
| Nationwide coverage | Fetch per county on demand from national APIs, plus four small national files loaded at startup. Nothing is precomputed per county. |
| County pick **and** box select | County click is the primary path. Box select resolves to at most `MAX_COUNTIES` counties. |
| Sites plus county summary | Needs are scored per county. Assets are individual map points. |

### Non-goals for the hackathon

- Census-tract or block-level analysis.
- Walkability or routing of any kind.
- Earth Engine (auth setup, quotas and latency make it a stretch item only).
- User accounts, saved reports, PDF export.

## 2. Rules for Claude working in this repo

1. **Never invent numbers, program names, dataset column names or API
   parameters.** Open the file or the docs first. If you cannot confirm it, leave
   a `# VERIFY:` comment and tell the user.
2. **Gemini writes words; code supplies every number.** Gemini never chooses
   funding programs, capacities or rankings.
3. **Every estimate is labelled.** Any computed capacity, energy or household
   figure carries `is_estimate: true` and a list of assumptions.
4. **A failed data source must not fail the request.** Each source has a 15 s
   timeout, is cached, and on failure adds an entry to `source_status` while the
   rest of the report is returned.
5. **`backend/app/models.py` is the API contract.** Change it first, then mirror
   it in `frontend/src/types.ts`. Do not let them drift.
6. Do not add a database, ORM, Docker, auth, state library or Earth Engine
   unless the user asks.
7. Keep changes small. Run `pytest` and `npm run build` before saying a task is
   done.
8. Python 3.11+, type hints everywhere, `httpx.AsyncClient`, Pydantic v2, `ruff`.
   Frontend is TypeScript in strict mode with plain React state.

## 3. Architecture

```
Browser (React + Mapbox GL)
   |  POST /api/analyze  {county fips} or {bbox corners}
   v
FastAPI
   |- geo.py        resolve fips / bbox -> county polygons
   |- pipeline.py   per county, run sources concurrently (asyncio.gather)
   |    |- Census ACS API        -> needs inputs (county + national)
   |    |- NLR PVWatts API       -> solar yield at centroid and top sites
   |    |- NLR station API       -> EV chargers
   |    |- Geoapify Places       -> schools, libraries, colleges
   |    |- RE-Powering file      -> brownfields, landfills, mine lands
   |    |- LMOP file             -> landfills and gas projects
   |    |- NRI file              -> natural hazard risk
   |- needs.py      rule-based need flags and severity
   |- matching.py   need + asset -> opportunity, ranked
   |- estimates.py  capacity / energy / households, labelled
   |- funding.py    curated program table -> matches
   |- narrative.py  Gemini structured output, template fallback
   v
CountyReport JSON  ->  map markers + results panel
```

Storage is in-memory dataframes plus a disk cache (`backend/.cache/`, JSON files
keyed by source and arguments). Target latency: under 10 s cold, under 1 s warm
for one county.

## 6. Data sources: how to call each one

### 6.1 County boundaries (startup file)

- Download the Census cartographic boundary county file at 1:5,000,000
  (`cb_<year>_us_county_5m`). **VERIFY** the latest year and URL on census.gov.
- `prep_data.py` converts it to `data/counties.geojson` with properties
  `GEOID` (5-digit FIPS), `NAME`, `STUSPS`, plus centroid lon/lat and area.
- The backend loads it into a Shapely `STRtree`. The frontend loads the same
  file from `GET /api/counties.geojson`.

### 6.2 Census ACS 5-year (on demand)

```
GET https://api.census.gov/data/{ACS_YEAR}/acs/acs5
    ?get=NAME,<vars>&for=county:{CCC}&in=state:{SS}&key=...
GET ...?get=NAME,<vars>&for=us:1&key=...        # national baseline, cache 30 days
```

Limit is 50 variables per call. Variables (confirm each label against
`https://api.census.gov/data/{ACS_YEAR}/acs/acs5/variables.json`, because the
Census Bureau changes variables between releases):

| Metric | Formula |
|---|---|
| Population | `B01003_001E` |
| Median household income | `B19013_001E` |
| Poverty rate (context) | `B17001_002E / B17001_001E` |
| Unemployment (context) | `B23025_005E / B23025_003E` |
| Pre-1980 housing share | `sum(B25034_007E..011E) / B25034_001E` |
| Fuel oil + propane heat share | `(B25040_003E + B25040_005E) / B25040_001E` |
| Electric heat share (context) | `B25040_004E / B25040_001E` |
| Mobile home share | `B25024_010E / B25024_001E` |
| Renter share | `B25003_003E / B25003_001E` |
| No-vehicle share | `B08201_002E / B08201_001E` |
| Drive-alone share | `B08301_003E / B08301_001E` |
| Commute 45+ min share | `sum(B08303_011E..013E) / B08303_001E` |

Negative sentinel values (for example `-666666666`) mean "no data"; treat as null.

### 6.3 NLR developer network (on demand)

The `developer.nrel.gov` domain was retired on 2026-05-29. Use
**`https://developer.nlr.gov`** only. Old tutorials and packages still point at
the dead domain.

PVWatts v8, one call per point with a 1 kW system so the result is yield per kW:

```
GET https://developer.nlr.gov/api/pvwatts/v8.json
    ?api_key=...&lat=..&lon=..&system_capacity=1
    &module_type=0&losses=14&array_type=0&tilt=20&azimuth=180
-> outputs.ac_annual   (kWh per kW per year)
```

Call it for the county centroid and for at most 5 top-ranked sites. Cache by
coordinates rounded to 2 decimals.

EV stations, one call per state, cached 24 h, then filtered by county polygon:

```
GET https://developer.nlr.gov/api/alt-fuel-stations/v1.json
    ?api_key=...&fuel_type=ELEC&state=NY&status=E&access=public
-> fuel_stations[] with latitude, longitude, station_name
```

**VERIFY** parameter names and rate limits in the docs before coding.

### 6.4 Geoapify Places (on demand)

```
GET https://api.geoapify.com/v2/places
    ?categories=education.library,education.college,education.university,education.school
    &filter=rect:{west},{south},{east},{north}&limit=500&apiKey=...
-> features[].properties: name, categories, lat, lon, city, place_id
```

Query the county bounding box, then filter by point-in-polygon. Cache 7 days.
A request returns at most 500 places, so a full box is split into quarters
(see `sources/geoapify.py`). Key: `GEOAPIFY_API_KEY`. Geoapify's data comes
from OpenStreetMap, whose license requires the credit "© OpenStreetMap
contributors" wherever it is shown; keep it in the footer.

### 6.5 EPA RE-Powering dataset (startup file)

- Download the "RE-Powering Screening Dataset (xlsx)" from
  `https://www.epa.gov/re-powering/how-identify-sites`. It is about 78 MB and
  covers more than 190,000 sites pre-screened for renewable energy potential.
- `prep_data.py`: open it, **print the column names**, then map the real columns
  to our schema: `site_id, name, site_type, lat, lon, acres, state, county_fips,
  solar_flag, wind_flag`. Do not guess column names. Write `repowering.parquet`.
- Lookup at request time is a dataframe filter by county FIPS (or by polygon if
  the file has no FIPS column).

### 6.6 EPA LMOP database (startup file)

- Download the landfill-level file from
  `https://www.epa.gov/lmop/lmop-landfill-and-project-database`.
- Same approach: inspect columns, then keep `landfill_id, name, lat, lon,
  county, state, status, project_status`, plus any gas-flow or capacity
  columns that exist.
- The database is not a complete inventory of US landfills. Say so in the UI.

### 6.7 FEMA National Risk Index (startup file)

- Download the county-level CSV from `https://hazards.fema.gov/nri/data-resources`
  (version 1.20, December 2025).
- Keep county FIPS, the overall rating, and the ratings for riverine or inland
  flooding, wildfire, drought and heat wave. **VERIFY** field names in the NRI
  data dictionary.

### 6.8 Gemini (on demand)

See section 12.

### Box selection rule

1. Find counties whose polygon intersects the box.
2. Keep a county if its centroid is inside the box **or** at least 25% of its
   area is inside.
3. Sort by overlap area, descending. Return the first `MAX_COUNTIES`.
4. If more matched, set `truncated: true` and a message asking the user to zoom
   in. Do not error.

## 8. Need scoring

For every ACS need, compare the county to the national figure from the same API.

```
ratio    = county_value / national_value        # inverted for low_income
severity = round(100 * clamp((ratio - 1.0) / 0.5, 0, 1))
level    = "high" if ratio >= 1.25 else "elevated" if ratio >= 1.10 else "none"
```

For `low_income`, `ratio = national_income / county_income`. Only needs with
level `elevated` or `high` are returned. Thresholds live in `config.py`.

Non-ACS needs:

| Need | Rule |
|---|---|
| `ev_charging_gap` | `high` if zero public stations in the county. Otherwise compare stations per 10,000 residents to `EV_BENCHMARK_PER_10K`, a config constant computed once from the national station count and population. Comment the date it was computed. |
| `landfill_gas_uncaptured` | `high` if the county has an LMOP landfill whose status marks it as a candidate with no operational project. **VERIFY** the status values in the file. |
| `hazard_risk` | `high` if any of the four tracked hazards is rated "Relatively High" or "Very High"; `elevated` for "Relatively Moderate". Record which hazard. |

## 9. Solutions and matching

`data/solutions.json` holds the rules. MVP set:

| `solution_id` | Solution | Hosted at | Triggered by any of |
|---|---|---|---|
| `community_solar` | Community solar on reclaimed land | brownfield, closed landfill, mine land | `low_income`, `renters`, `mobile_homes` |
| `resilience_hub` | Solar-and-battery resilience hub | school, library, college | `hazard_risk`, `low_income` |
| `weatherization_clinic` | Weatherization and heat-pump sign-up clinic | library, school | `old_housing`, `delivered_fuel_heat`, `mobile_homes` |
| `public_ev_charging` | Public EV charging | school, library, college | `ev_charging_gap`, `long_commute`, `drive_alone` |
| `landfill_gas_energy` | Landfill gas-to-energy | LMOP candidate landfill | `landfill_gas_uncaptured` |

Matching:

```
for each solution:
    matched_needs = flagged needs in solution.triggers
    if none: skip
    candidates = county assets whose type is in solution.hosts
    if none: skip
    pick up to 2 best assets (largest acres for land; nearest to the county
        population centroid, or simply first by name, for buildings)
    score = mean(severity of matched_needs) * asset_factor
            asset_factor = 1.0 if the asset has the data the estimate needs,
                           else 0.7
return the top 6 opportunities by score
```

Stretch solutions, each needing a stretch asset: small hydro at a non-powered
dam, farm digester, agrivoltaics, biomass heat for public buildings, wind on
mine land, solar canopy on paved lots, shade trees and depaving, rain gardens.

## 10. Estimates

Constants live in `estimates.py` with a comment naming the source. Every one is
an assumption and appears in the `assumptions` list shown to the user.

| Estimate | Formula | Assumptions to state |
|---|---|---|
| Solar capacity on land | `acres * 0.6 / 6` MW | 60% of site usable; 6 acres per MW. **VERIFY** against an NLR or EPA figure. |
| Annual energy | `capacity_kw * pvwatts_ac_annual_per_kw` | PVWatts typical-year yield, fixed tilt 20° |
| Households equivalent | `annual_kwh / 10_500` | Average US household use. **VERIFY** against the latest EIA figure. |
| Resilience hub size | fixed `100 kW` | Illustrative rooftop array |
| Landfill gas | Use capacity or flow columns from LMOP if present; otherwise no number | None invented |

Jobs and bill savings are **out of the MVP**. Do not add multipliers without a
cited source.

```json
  "agency": "EPA",
  "type": "grant",

  "eligible_asset_types": ["brownfield"],
  "status": "open",

  "verified_on": "2026-11-13"
```

`status` is one of `open`, `open_with_deadlines`, `paused`, `uncertain`,

labels an `unverified` or `uncertain` program as available.

Seed entries, as checked on 2026-11-13:

| Program | Status | Notes |
|---|---|---|
| Elective (direct) pay for clean electricity credits (48E / 45Y) | `open_with_deadlines` | Still available to governments, schools and nonprofits. Wind and solar had to start construction by 2026-07-04 or must be in service by 2027-12-31. Other technologies such as hydro, geothermal and storage have later deadlines. Foreign-entity sourcing rules apply. |
| Energy community bonus | `open_with_deadlines` | A 10-point adder on the credits above, not a grant. Only applies if the base credit does. |
| EPA Brownfields grants, FY 2027 | `open` | Applications due 2027-01-21. No Multipurpose grants this round. |
| USDA REAP | `uncertain` | Grant awards were halted in March 2026 and the funding notice rescinded in April. A rewritten rule took effect 2026-10-16. Eligible applicants are farms and rural small businesses, not governments. Check for an open notice. |
| DOE Weatherization Assistance Program | `uncertain` | Funded at $329M for FY 2026. The FY 2027 budget request proposes $0. Households apply through state and local agencies. |
| FEMA hazard mitigation grants | `unverified` | Not checked. |
| State programs | `unverified` | Add entries for the states of your demo counties. |

Matching: a program matches an opportunity when the solution is in
`eligible_solutions` and, if `eligible_asset_types` is set, the asset type is in
it. Sort `open` first.

## 12. Gemini narrative

- SDK: `google-genai` (`from google import genai`; `genai.Client()` reads
  `GEMINI_API_KEY`).
- Model: `GEMINI_MODEL`, default `gemini-3.8-flash`. Model names change often;
  confirm at `https://ai.google.dev/gemini-api/docs/models`.
- One call per county, structured output with a Pydantic schema, results cached
  by a hash of the input payload.

```python
class OpportunityNote(BaseModel):
    opportunity_id: str
    text: str            # <= 60 words

class Narrative(BaseModel):
    summary: str         # <= 90 words
    opportunity_notes: list[OpportunityNote]
    caveats: list[str]

resp = await client.aio.models.generate_content(
    model=settings.gemini_model,
```

Prompt rules to include verbatim:

## 15. Risks and fallbacks

| Risk | Fallback |
|---|---|
| Geoapify slow, rate-limited or out of quota | Return the report without public buildings; use the cache for demo counties |
| Census API unavailable | Fixtures for demo counties; surface the failure in `source_status` |
| Gemini error, timeout or invented number | Template narrative |
| Mapbox token or billing problem | MapLibre GL JS is API-compatible for everything used here |

| Rural county has no assets of a type | The opportunity is skipped; the panel says which asset types were not found |
